# 整體規劃與視覺優化

## 從零開始

確認主要使用者、核心任務、使用情境、必要資料與裝置。已有答案就沿用；未選框架不妨礙先做產品設計。

以任務建立頁面和導覽，不把「首頁／地圖／我的」等案例當固定清單。說清楚主要操作、返回、深層頁面與中斷恢復，再安排內容優先順序。

視覺探索在方向未定時有用：用少量有實質差異的布局、資訊層級或品牌表達來比較，而非只換顏色。已有明確參考或只改一個元件時不用多案。

選定方向後定義共用規範：語意色彩、繁中文字體與層級、間距、圖片比例、圓角／陰影、元件變體，以及載入、空資料、停用、錯誤、成功狀態。優先讓程式元件引用同一規範，避免逐頁硬編碼。

先用代表頁驗證布局與互動，再擴展；若使用者只要規劃，就停在規劃交付，不自行進入產品實作。

## 既有介面打磨

| 症狀 | 先檢查 | 可能的最小改善 |
|---|---|---|
| 看不出重點 | 主要任務、閱讀順序、主次資訊 | 調整層級、分組與主要操作位置 |
| 很擠、卡片太多 | 重複資訊、容器層級、間距 | 合併重複、簡化容器，不刪必要資料 |
| 太平淡 | 品牌、內容、對比與節奏 | 選一個有理由的視覺焦點 |
| 跨頁不一致 | 主題、元件變體與規範引用 | 修共用來源，不逐頁堆補丁 |
| 長字或鍵盤出現就壞 | 約束、捲動、字體放大與安全區域 | 修布局及輸入流程，不縮小全部文字 |
| 操作生硬 | 真實狀態、回饋時機與可取消性 | 明確回饋後再加必要動效 |

以上是候選原因，需用畫面、程式與實際操作確認。不能從字體、漸層或卡片樣式直接判定品質或是否由 AI 生成。

## 平台與交接

- Android 依目標版本及現有元件參考 Material；iOS 參考 Apple HIG。跨平台共享品牌與語意規範，導航、返回、鍵盤與系統行為仍需各自處理。
- 保留可讀繁體中文、長標籤、字體放大與深淺主題。平台尺寸單位與觸控規格使用當下官方資料，不把 Web px 一律當成 dp 或 pt。
- 控制項提供可及名稱與真實角色／狀態，例如開關可讀出開或關；選取、警告與成功不要只用顏色區分。依目標平台驗證讀屏、焦點順序與觸控操作。
- 若交付可編輯設計稿，保留文字、圖層、元件、變數與素材；生成圖片只作視覺目標。
- 交接包含目標畫板／截圖、元件與變數對應、素材、框架、真實／模擬資料、互動狀態及驗收條件。Figma 或 D2C 的輸出要與現有架構比對，不能直接假定為完整可用 App。
