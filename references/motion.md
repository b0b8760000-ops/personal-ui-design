# 動畫與互動

先分辨：App 內回應操作的即時動效、播放的動畫素材、設計工具原型、展示影片。交付最後兩者不能證明前兩者已實作。

## 依框架選方法

| 目標 | 優先考慮 | 適合的工作 |
|---|---|---|
| Flutter | 現有 Material／Cupertino 行為、隱式動畫、Controller／Tween、Hero | 按壓、展開、列表、共享元素、可控制動畫 |
| React Native／Expo | 現有導航動效、Reanimated、Gesture Handler；Expo 動畫 Skill 按需使用 | 跟手、拖曳、吸附、手勢與觸覺回饋 |
| Kotlin／Compose | Compose 動畫與現有 Material 元件 | 狀態值、顯示隱藏、尺寸、頁面切換 |
| SwiftUI | 系統元件、animation／transition 與目標版本可用 API | 狀態轉換、頁面與元件動畫 |
| Web／PWA | CSS／WAAPI；較複雜 React 動效再評估 Motion 開源 npm 套件 | 只用開源 API 與自行實作，不使用另購範例或外掛 |
| 預製向量動畫 | 已確認免費的 Lottie runtime 與免費授權素材 | 素材取得與修改／匯出也要免費；不以播放器授權代替素材授權 |

以上是選用方向，不保證某版本或平台已支援特定 API；實作時查官方文件與專案依賴。React DOM／CSS 程式不能直接當成 Flutter 或 React Native 原生程式。

Lottie 適合預製動畫播放，仍需驗證素材授權與目標播放器相容性。找不到可免費取得與修改的動畫時，改用框架動畫或自行編寫 SVG。互動角色可用程式狀態機控制自有素材；不預設需要外部動畫編輯器，也不承諾全自動。動畫不取代頁面導航或服務成功判定。

## 把感覺寫成可實作規格

記錄「觸發操作 → 元素及相關元素如何變化 → 最終資料狀態 → 重複操作／取消／失敗 → 減少動態 → 驗收」。時長與曲線依平台、距離和用途選擇，不把單一毫秒數當萬用標準。

| 模式 | 視覺候選 | 必須維持的功能 |
|---|---|---|
| 按壓／選取 | 縮放、色彩或選取指示移動 | 真實可用／停用、選取與焦點一致 |
| 展開／收合 | 容器尺寸與箭頭平順改變 | 長文字可讀、焦點與捲動正確 |
| 卡片到詳情 | 共享元素位置與尺寸過渡 | 正確資料、返回及取消仍可用 |
| 列表新增／刪除 | 進出場與鄰項讓位 | 真實資料結果；必要時撤銷、失敗恢復 |
| 拖曳排序 | 被拖項跟手、其他項讓位 | 最終順序更新，取消恢復，提供點按移動等替代 |
| 主題切換 | 淡入或局部揭露 | 不扭曲內容，快速重切以最新狀態為準 |
| 儲存／同步 | 處理中、成功或錯誤回饋 | 區分本機已保存、遠端已接受與真正同步完成，依各階段證據判定 |
| 互動角色 | 閒置、忙碌、成功與失敗表情 | 狀態機與 App 狀態同步，不遮擋操作 |

## 驗證重點

動畫要能處理快速連點、途中返回、頁面卸載與操作取消；完成回呼不能讓過期請求覆蓋新狀態。採樂觀更新時說清楚暫時與已保存狀態及回復方式。

例如離線時成功寫入本機，只能顯示「已儲存、待同步」；遠端接受工作但尚未處理完成，也不能提前顯示「已同步」。動畫根據已確認的資料階段回饋，不反過來決定資料狀態。

拖曳不要成為重要功能的唯一方式。非必要動態提供簡化回饋，保留狀態資訊；遵循目標平台的減少動態機制。使用系統元件已有的動效前先觀察，避免重複套效果。

在目標裝置檢查掉幀、長列表、模糊／粒子合成、素材載入、離頁後資源及耗電風險。沒有量測就不宣稱流暢幀率、效能提升或全裝置相容。
